# 주식 포트폴리오 리밸런싱 프로그램 — 설계 노트

> FRMS(IoT 요구사항관리 시스템)와는 별개의 도구다. 저장소를 공유할 뿐 도메인이
> 다르므로 코드는 `rebalancer/` 아래에 독립 패키지로 둔다.

## 1. 기본 철학: 손익(P&L) vs 내재가치

리밸런싱의 **목표 비중**은 보유 손익(미실현 P&L)과 무관하게, 종목의 **내재가치**
기준으로만 정한다. 매수원가는 매몰비용이며 미래 기대수익과 무관하다. 손익 기준
리밸런싱("수익 난 종목 비중 축소, 손실 종목은 본전까지 보유")은 처분효과
(disposition effect)라는 행동편향을 그대로 프로그램에 옮기는 것이다.

다만 **실행(매도) 단계**에서는 보유 손익이 실질적으로 중요하다 — 특히 해외주식
양도세 손익통산. 따라서:

```
① 밸류에이션 모델        → 목표 비중 산출  [손익 개입 X]
② 리스크/분산 제약        → 목표 비중 조정
③ 실행 레이어(매매 주문)  → 여기서만 보유 손익·매수 로트 사용 (세금 최적화 등)
```

이 설계 문서와 `rebalancer/` 코드는 ①·②만 다룬다. ③(세금 최적화 매도 로직)은
범위 밖이며 향후 별도로 다룬다.

## 2. 대상 범위

- 시장: 국내 상장주식(KOSPI/KOSDAQ)
- 포트폴리오 규모: 5~20종목 — 종목별 개별 분석이 가능한 규모
- 데이터 소스(예정, 아직 미구현): DART OpenAPI(재무제표), KRX/증권사 API(시세)

## 3. 내재가치 산출 방법론

종목 유형별로 다른 모델을 쓰고, 결과는 점추정이 아닌 시나리오 레인지(bear/base/bull)로
산출한다.

| 종목 유형 | 방법론 | 이유 |
|---|---|---|
| 제조업/IT/일반 기업 | 2단계 DCF (FCFF) | 표준적, 예측기간+영구가치 구조 |
| 금융업/지주회사 | 잔여이익모델(RIM) | FCF 개념이 왜곡되는 업종. 터미널밸류 의존도가 낮아 DCF보다 가정에 덜 민감 |
| 성숙 배당주 | DDM(교차검증용, 선택) | DCF/RIM 결과의 sanity check |
| 전 종목 공통 | 자기 자신의 과거 PER/PBR 밴드 | 상대가치는 sanity check 용도로만. 글로벌 피어 비교는 코리아 디스카운트로 왜곡됨 |

DCF는 WACC·영구성장률 가정에 결과가 극도로 민감하므로 **항상 3개 시나리오**로
계산하고 단일 값을 쓰지 않는다.

## 4. 종목 선정 퍼널

```
전체 유니버스 (~2,500개)
   → ① 결격 배제 필터   (관리종목/거래정지/스팩/우선주/감사의견 비적정/제재이력)
   → ② 재무 건전성/퀄리티 스크리닝  (시총·거래대금 하한, 부채비율, 이자보상배율, 연속흑자)
   → ③ 저평가 후보 1차 필터  (자기 역사적 PER/PBR 밴드 하위)   → 30~50개로 축소
   → ④ 개별 DCF/RIM 정밀 분석   → 안전마진 산출
   → ⑤ 정성 필터 (사업 이해 가능성, 지배구조 리스크) — 사람이 개입, 자동화 불가
   → ⑥ 분산 제약 (섹터 비중 상한, 상관관계 높은 조합 회피)
   → 최종 5~20종목 → §5의 비중 함수 적용
```

## 5. 안전마진 → 목표비중 변환

```
안전마진(margin_i) = (내재가치_base - 현재가) / 내재가치_base

① 클리핑        m' = clip(margin, -0.30, +0.50)         — 모델 오차 극단값 제거
② 비선형 변환    s = sign(m') * sqrt(|m'|)                — 딥밸류 몰빵 방지(체감)
③ 리스크 조정    r = s / σ (연변동성)                      — 변동성당 안전마진
④ 베이스라인 블렌딩  w_raw = α*normalize(max(r,0)) + (1-α)*baseline
                                                          — 밸류에이션 과신 방지
⑤ 정규화 + 상하한 캡 (최소 3~5%, 최대 20~25%, waterfall 재분배)
                — margin이 하한 이하인 종목은 강제로 비중 0 (편출)
```

α(모델 신뢰도)는 처음엔 보수적으로 0.3~0.5에서 시작하고 추후 백테스트로 조정한다.

## 6. 리밸런싱 실행 트리거

거래비용·세금을 아끼기 위해 미세한 괴리로는 매매하지 않는다.

```
|현재비중 - 목표비중| >= band(기본 5%p) 인 종목만 매매 실행
```

## 7. 구현 범위 (이번 단계)

`rebalancer/` 패키지에 다음을 구현한다 (순수 로직, 외부 데이터 연동은 후속 작업):

- `valuation/dcf.py` — 2단계 FCFF DCF, 시나리오별 계산
- `valuation/rim.py` — 잔여이익모델
- `screening.py` — §4의 ①②③ 필터 함수
- `weighting.py` — §5의 5단계 파이프라인
- `rebalance.py` — §6의 밴드 기반 매매 트리거

DART API 연동, PER/PBR 히스토리 수집, 정성 필터(⑤)의 UI/워크플로는 범위 밖이며
후속 단계에서 다룬다.
